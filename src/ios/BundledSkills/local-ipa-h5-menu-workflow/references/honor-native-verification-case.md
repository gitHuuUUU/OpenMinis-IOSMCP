# 原生 IPA 验证与独立 H5 绘制启动：静态案例

项目：`D:/Codex/杂交版植物大战僵尸/honor-verification/`。**V1 已被用户实机截图证实失败：仍出现授权激活弹窗。V2/V3 是修复候选，尚未真机成功验证。**

提供包的 cimgui 通过 `@loader_path/PK` 加载第三方模块，PK 中的实际绘制为内嵌 Canvas2D + H5GG 原生读数桥；没有套用上一项目的 Cocos 战斗方法。

关键经验：输入包已被部分修改。授权布尔入口返回真、CGRect透传、运行模式分支和部分偏移桩已存在；只改更多返回值既重复也可能破坏绘制。通过符号、指令、ObjC selector 和构造器表，发现独立 `Aegis.load → VenomH5GGStartAuthorized` 链已存在，而两个验证构造器仍会启动。针对**这个精确 SHA-256 版本**，只停用两个验证构造器，保留其余 C++初始化、dyld callback、端口代理与绘制链。

验证：两指令范围差异、96组ARM64返回ABI/滑移、19段原生代码及完整HTML保留、真实签名页哈希、1238个未修改ZIP记录逐字节及全IPA CRC。游戏原生源工程没有提供，源码交付仅称本次补丁/测试/打包源码和提取的HTML/JS。

不要将这个“两个RET”的方案迁移为通用破解模板。新包可能需要验证成功回调、配置材料或构造器初始化；必须重新核对依赖。布局参数、指针地址上界和函数偏移不能混淆。本例曾将极大常量误判成函数偏移，后沿调用参数证实是地址上界，故保留原代码。

工具经验：Ghidra自动ObjC分析可因混淆达到时限；记录失败、不声称获得完整伪代码。使用实际Mach-O解析、Capstone和独立调用链复核继续非阻塞部分。所有动态效果、坐标准确性和后台恢复仍须真机验证。

## V1 漏项与 V2

V1 只追 PK 内部验证，没有追完依赖闭包。PK 还加载 `cola.framework/cola`；其独立 `ColaGateEntry → ColaGateAuth.start → validateLocalOrShowActivation → showActivationUIWithMessage` 完全没有被停止。应从 Mach-O 依赖递归查找所有附加模块的独立初始化，不能因为主插件授权被改就断言整包不再验证。

cola 的 Ghidra CLI 分析成功，得到原生伪代码。V2 保留原修改，仅增加 cola 激活构造器 RET；不删除该框架，也不盲改独立路由检测、远控退出分支。新增实际构造器指令仿真复现 V1 仍会派发 callback 0x7720、V2 不再派发；共9测试/144 ABI组合通过，仍不能替代真机测试。**手工交付需一起替换 PK 与 cola，单独导入 PK 无法修复此漏项。**

用户随后要求脱离验证服务器。V3 在明确新增范围下再停止 cola 的远控配置自动启动（0x413d4），不是伪造成功响应；保留游戏网络和绘制。12项回归/192 ABI组合、授权与远控构造器仿真不再派发callback，包级原样记录和CRC通过后交付。没有设备抓包，不宣称完全没有其他动态触发。原 UDP socket/connect/getsockname 路由检测及外部UI资源请求仍存在，不能将“关闭验证启动”说成“所有网络完全离线”。
